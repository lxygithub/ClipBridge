# ClipBridge 双端 UI · 方向稿

统一 spec：手机 392×832（Android 15，状态栏 24dp、底部手势条）、Windows 历史窗口 1010×约 520（可拉伸）、
同一套内容（11-26 当天的 128 条真实条目：文本、URL、文件截图、终端命令）。

三版差异落在**版式结构**上，不是配色：一版是四列扫描表；一版是上下两只托盘 + 一条连接线；一版是通道 + 附着水滴。

---

## 方向 1 · 深底情报台（`dir-1-dossier.html`）

| 栏 | 内容 |
|---|---|
| 逻辑与来源 | 报刊索引版式（Pentagram 的信息设计传统）＋监控台的高密度表。借的是「四列定宽 + 等宽数字」这一条机制。 |
| 主屏形态 | 一条流水：时间 / 方向 / 内容 / 元数据，四列固定，扫读不用左右跳。 |
| 签名处 | 方向列：↓ 琥珀、↑ 青柠，且整行只在左侧 2px 亮一条，不整块染色。 |
| 数据形状 | 表格 + 顶部一个「128 条今日」的大数字，作为密度锚点。 |
| 颜色回答什么 | 只回答方向：来的是琥珀、去的是青柠，其余全灰阶。 |
| 嗓音 | 短句、术语直接（「监听中 · 队列 0 · 托盘在线」），不寒暄。 |

Windows 同构：多一列搜索 + 筛选 chip；底部状态栏放热键提示；右侧再补托盘菜单与桌面通知两块小面板。

---

## 方向 2 · 双面收发台（`dir-2-trays.html`）

| 栏 | 内容 |
|---|---|
| 逻辑与来源 | 邮件客户端把「收件 / 发件」拆成两条独立时间线的机制；纸张与印章的质感语言来自印刷品。 |
| 主屏形态 | 上下两只托盘：上「来自电脑」、下「发往电脑」，中间一条细线就是连接本身。 |
| 签名处 | 中间那条线：两端各一个圆点，中间写「直连」；断线时变虚线，不用去设置里查状态。 |
| 数据形状 | 两条并列清单，各自有自己的时钟（手机上「已送达」，电脑上「已写盘」）。 |
| 颜色回答什么 | 回答归属：蓝墨=电脑、朱红=手机，状态用绿。 |
| 嗓音 | 书面、克制，留一条批注解释「为什么还没写进剪贴板」。 |

Windows 是左右两栏围着一根竖脊，中间节点写延迟；下面补托盘菜单与手机通知的两块验收面。

---

## 方向 3 · 一条通道（`dir-3-conduit.html`）

| 栏 | 内容 |
|---|---|
| 逻辑与来源 | 网络监控工具把连接画成一条带方向的竖线、用脉冲表示流量的机制。 |
| 主屏形态 | 通道视图：上节点 = 电脑，下节点 = 本机，中间一条渐变竖线（青→琥珀），条目挂在线上，越新越靠上。 |
| 签名处 | 那条线本身：直连时是实线 + 一个呼吸点，暂停时整条变暗灰。 |
| 数据形状 | 时间轴 + 双向流量条（下行 98 / 上行 30），再给一个 24 小时柱图。 |
| 颜色回答什么 | 回答方向，与方向 1 同一套语义（青=上行、琥珀=下行），但换成线的两端而不是行首。 |
| 嗓音 | 工程化：「12ms · 打洞直连 · relay euc1 仅做发现」。 |

Windows 左栏 300px 是通道侧写（两端节点 + 竖脊 + 流量柱），右栏是日志表。

## 落选的三张（写出过但不做完整版）

| 候选 | 为什么没选 |
|---|---|
| 卡片瀑布流（每条一张卡） | 128 条的密度撑不住，扫描成本高，跟「一眼找上一条」的目标反向。 |
| 单条大卡 + 顶部轮播（一次只看一条） | 是阅读器不是工具，回到手机上翻历史要滑很多次。 |
| 双栏网格（左手机右电脑并排缩略） | 结构上和方向 2 重复，只是把竖线换成横线。 |

---

## 实现映射（定稿后怎么落地）

| 面 | 技术 | 说明 |
|---|---|---|
| Android | Jetpack Compose | 三版都能做；方向 2 的两托盘用 `Column` + 分隔线，方向 3 的通道用 `Canvas` 画线 + `LazyColumn` 附着，方向 1 用固定列宽的 `Row`。 |
| Windows | 现有 Win32，改为自绘 | 当前是原生 EDIT/LISTBOX 控件；选任何一版都要换成「自绘列表 + 自绘标题栏」，否则字体、行高、颜色都对不上稿子。工作量约 1 天。 |

⚠️ 需要你确认的一点：Windows 端要不要接受「自绘重写」（换来稿子 1:1 还原），
还是保留原生控件只做换色换字号（还原度大概 60%）。
